# AI 解读服务运行说明

## 调用链路

浏览器在用户单次勾选授权后，向同源 `POST /api/v1/interpret` 发送经过事实包校验的命盘契约。Worker 检查授权版本、契约校验状态、支持范围、请求大小和证据路径，再通过 DeepSeek Chat Completions JSON Output 请求结构化回答，并在服务端复核输出结构、证据路径和风险措辞。密钥只从 Site Worker 的运行时环境读取，不进入浏览器、源码或构建产物。

前端继续由同一个 Worker 提供，不需要另开服务或跨域访问。`GET /api/health` 仅返回是否配置了模型，不披露密钥和模型名称。

## 部署密钥

Site 运行环境需要以下密钥/配置：

- `DEEPSEEK_API_KEY`：以 secret 保存的 DeepSeek API key。
- `DEEPSEEK_MODEL`：DeepSeek API 的模型 ID；当前官方文档列出的快速测试选项为 `deepseek-flash`。

当前版本不包含可用密钥，因此模型调用会明确返回 `AI_NOT_CONFIGURED`，不会调用模型或产生模型费用。接口固定指向 `https://api.deepseek.com/chat/completions`。请勿把密钥写入仓库、`.openai/hosting.json`、网页脚本或聊天记录。

## 用户数据

授权说明必须在用户操作前可见。发送内容包含本次排盘所需的出生日期、时辰、用于排盘的性别、八字/紫微盘面和校验事实；不含姓名或出生地。Worker 不主动写入数据库、日志或持久存储；请求内容也不得加入应用日志。调用模型会把事实契约发给 OpenAI API，实际数据处理还受模型供应商账户的数据控制与保留设置约束。

授权仅对当前一次点击有效，不存储在浏览器。新排盘会清除授权状态。改动发送字段、供应商、授权说明或授权版本时，必须同步复核隐私文案。

## 上线边界

当前 Worker 有请求体上限、同源 Origin 校验、单实例内存节流、超时和输出证据校验。内存节流会随 Worker 实例变化，不能当作可靠的全局配额或成本上限。为公开用户开放真实模型前，仍需增加可持久化/边缘级的全局速率限制、每日预算与告警、滥用处理和密钥轮换流程；这些条件未完成前，不要配置生产 API key。

此解读仅是传统文化资料的白话说明，不是科学诊断，也不提供医疗、法律、投资或必然事件预测。

## 真实模型启用前的评测门槛

不要把“JSON 合法、证据路径存在”当成事实正确。模型启用前，用不含真实用户身份信息的固定命盘样例建立人工复核集，至少覆盖：仅八字、仅紫微、双体系相互印证、双体系结论不一致、边界/低精度出生时间、当前运限，以及明确不支持的范围。

逐条记录以下结果：事实是否与引用路径一致、引用是否真正支持该句、是否越过支持范围、普通读者能否理解、是否出现确定性/恐吓/医疗/投资表达、规则边界是否交代清楚、输入中是否仅含授权字段。对照模型或提示词版本保留可复核的匿名输出，不保存生产用户的出生资料作为评测样本。

启用前的建议门槛：所有具体判断均可追溯且无捏造事实；越界与高风险表达为 0；每个输出都明确事实不足与传统文化解释的局限；至少 5 位非专业读者对“看得懂、知道依据、知道不能据此做什么”分别打分，均值不低于 4/5。任一门槛未达到，就修订提示词或输出，不通过放宽校验规则来掩盖问题。
