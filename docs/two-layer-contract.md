# 两层合同：事实门禁（A）与分析审查（B）

来源：`plan-v3.json` T1 裁定。plan-chartinfo 三轮 FAIL（r734/r735/r736）后确认，
原 T6/T7 把两件不同的事混成了一个验收：「数据事实是否齐备」与「模型是否按知识做了解读」。

## A 层：数据事实门禁（可自动化）

**只回答一个问题**：这一项所需的事实，是否存在、可解析、结构有效、并通过可机械验证的一致性检查。

它**不声称**分析已执行，也**不评价**解读质量。

### 完成判据（工程完成，不等于可交付）

1. 固定顺序输出 15 项，顺序即 §16 编号 1..15
2. 每个状态都有**可复现依据**（检查项、解析路径、命中的规则）
3. 每处缺口给出 `{code, path, reason}` 三元组
4. 错误输入**不产生假 ready**
5. 允许真实样例保留 `blocked`——那不是缺陷，是事实层确实缺能力

### 单个盘的「事实齐备」判据

15 项全部为 `ready` 或**有明确理由的** `not_applicable`。

**这不代表 B 层完成，也不代表报告可交付。**

### 状态语义

| 状态 | 含义 |
|---|---|
| `ready` | 该项的**完整事实合同**已满足 |
| `conditional` | 事实存在，但必要的一致性核验或来源核验尚未完成 |
| `blocked` | 缺必需事实、输入无效、或该项所需能力不可用 |
| `not_applicable` | **仅**由明确的适用性规则产生（如主题明确不涉婚） |

### 禁止的升级方式

不能用 `options.verified` 这类布尔标记、也不能用 `blockedEvidence.verificationPassed`
作为升级为 `ready` 的唯一依据——那等于用"调用方说过了"冒充事实已核验。

本项目中：

- 第 6 项（忌之四态与禄转忌链）与第 15 项（同一大限逐流年）**本轮维持 blocked**，
  缺口已写在矩阵的 `evidenceModel` 里
- 矩阵中原有的**分析与口径要求**保留为待审项目，逐项区分「事实要求」与「B 层审查要求」，
  不能因为路径能解析到非空值就整体升级

## B 层：分析执行与独立审查

**执行**：模型按 §16 顺序逐项输出
`{id, status, text, factPointers, knowledgeReferences, limitations}`，
事实引用必须用同一份 ChartInfo 里**可解析**的路径，知识引用必须用**实际装载**的 source 与 anchor。

**审查**：由未参与生成的独立审查者逐项核对——
引用是否存在、引用是否支持对应文本、结论是否超出证据，并记录 §17 检查项与
`{reviewer, verdict, findings}`。

**这一层的数据层无法自证。** 数据层可以证明"事实齐备"，但不能证明"模型讲对了"。

### 不足时的行为

- 第 6、15 项及任何事实或知识不足的项：**只输出未完成原因，不编造推断**
- 第 11 项仅在主题明确不涉婚时标 `not_applicable`
- 装载 `unavailable`、超预算、模型调用失败或引用缺失：记录失败与缺口，**不伪造完成**

## 与用户目标的关系

```
排盘 → ChartInfo（已通）→ 挂 SKILL 知识（已通）→ B 层试读 → 独立审查
                                    ↑ 本轮要跑的是这里
```

A 层门禁是**前置卫生检查**，不是终点。用户的真实目标是 B 层能跑通并产出可追溯的解读。

## 实验性试读的定性

`scripts/run_section16.cjs` 的产物标记 `experimental`、**不可交付**。
判定"试读成功"只表示：链路确实运行、结果与审查可追溯。
**不表示 15 项已完成，也不表示正式报告合格。**
